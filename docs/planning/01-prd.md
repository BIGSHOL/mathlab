## 1. 문제 정의

### 1.1 현재 상황 (As-Is)

지금 수학 공부는 마치 **두꺼운 설명서만 읽고 요리하는 것**과 같습니다. 선생님이 칠판에 써주는 개념을 수동적으로 받아적고, 이해 여부와 관계없이 문제를 반복해서 풀게 됩니다. 기존 학습 앱들은 단순 반복과 주입식 방식이라 학생들이 금방 지루해하고, "수학 = 재미없는 것"이라는 인식이 굳어집니다.

### 1.2 목표 상황 (To-Be)

MathLab을 통해 학생들은 **게임 스테이지를 클리어하듯** 수학 개념을 단계별로 정복합니다. 처음엔 개념을 읽고, 점점 빈칸을 채우며, 마지막엔 백지에서 스스로 개념을 완성합니다. 포인트를 모으고, 레벨업하고, 친구들과 랭킹을 겨루면서 "수학이 재미있다"라고 느끼게 됩니다.

### 1.3 왜 지금인가? (Why Now)

학원에 딱 맞는 맞춤형 수학 학습 도구가 없습니다. 기존 도구들은 학원의 수업 전후 시간(비포/애프터 클래스)에 활용하기에 적합하지 않고, 학생들의 자기주도 학습을 유도하기 어렵습니다. 이미 학생들에게 검증한 결과, 이런 방식의 학습에 대한 니즈가 확인되었습니다.

### 2.4 민수의 하루 (시나리오)

오후 3시, 민수는 학원에 도착합니다. 수업 시작까지 30분이 남았습니다. MathLab을 열자 **"어서 와! 오늘의 미션이 기다리고 있어!"**라는 메시지와 함께 어제 이어서 할 개념이 표시됩니다.

민수는 "분수의 덧셈" 개념을 읽기 시작합니다. 그림과 함께 설명이 나와서 금방 이해가 됩니다. 읽기를 마치자 **"읽기 완료! +5 XP 획득!"** 메시지가 뜹니다.

다음은 빈칸 채우기. 방금 읽은 내용에서 핵심 단어가 빠져있습니다. 민수가 빈칸을 채우자 **"정확해! +10 XP!"**. 두 번째 빈칸 채우기는 더 많은 부분이 비어있지만, 방금 한 번 해봐서 자신감이 붙었습니다.

마지막으로 백지 쓰기! 아무것도 없는 화면에서 분수의 덧셈 개념을 직접 씁니다. **"스테이지 클리어! 레벨 12 달성! 🎉"** 민수는 랭킹 보드를 확인합니다. 오늘 3등이에요! 1등과 50 XP 차이라 내일 더 열심히 해봐야겠다고 다짐합니다.

## 3. 사용자 스토리

### FEAT-0: 공통 흐름 (계정 관리)
- [ ] 선생님(관리자)으로서, 학생 계정을 생성하고 부여할 수 있어야 한다. 왜냐하면 학원에서 직접 계정을 관리해야 하기 때문이다.
- [ ] 학생으로서, 부여받은 계정으로 로그인할 수 있어야 한다. 왜냐하면 내 학습 기록이 이어져야 하기 때문이다.
- [ ] 학생으로서, 로그인 상태가 유지되어야 한다. 왜냐하면 매번 로그인하는 건 귀찮기 때문이다.

### FEAT-1: 단계적 개념 학습 (MVP)
- [ ] 학생으로서, 수학 개념을 시각적 설명(그림/애니메이션)과 함께 읽을 수 있어야 한다. 왜냐하면 텍스트만으로는 이해하기 어렵기 때문이다.
- [ ] 학생으로서, 읽은 개념에서 빈칸을 채워볼 수 있어야 한다. 왜냐하면 직접 채워보면서 개념이 정착되기 때문이다.
- [ ] 학생으로서, 더 많은 빈칸(어려운 단계)을 채워볼 수 있어야 한다. 왜냐하면 점진적으로 보조 장치를 줄여야 진짜 이해가 되기 때문이다.
- [ ] 학생으로서, 완전히 빈 백지에서 개념을 직접 작성할 수 있어야 한다. 왜냐하면 이것이 진짜 이해했는지의 최종 검증이기 때문이다.
- [ ] 학생으로서, 각 단계를 완료하면 포인트(XP)를 받을 수 있어야 한다. 왜냐하면 보상이 있어야 계속하고 싶은 동기가 생기기 때문이다.
- [ ] 학생으로서, 포인트가 쌓이면 레벨업할 수 있어야 한다. 왜냐하면 성장하는 느낌이 재미를 유지시키기 때문이다.
- [ ] 학생으로서, 다른 학생들과 랭킹을 비교할 수 있어야 한다. 왜냐하면 건전한 경쟁이 동기를 높이기 때문이다.

### FEAT-2: 연습 문제 풀기 (v2)
- [ ] 학생으로서, 개념 학습 후 단계별 연습 문제를 풀 수 있어야 한다. 왜냐하면 문제를 풀어봐야 실전에 강해지기 때문이다.
- [ ] 학생으로서, 문제를 틀리면 즉시 피드백을 받을 수 있어야 한다. 왜냐하면 바로 교정해야 잘못된 개념이 굳어지지 않기 때문이다.

### FEAT-3: 학습 진도 관리 + 선생님 대시보드 (v2)
- [ ] 선생님으로서, 학생별 학습 진도를 한눈에 볼 수 있어야 한다. 왜냐하면 누가 어디서 막혀있는지 알아야 도울 수 있기 때문이다.
- [ ] 선생님으로서, 학생의 학습 데이터를 학부모에게 쉽게 공유할 수 있어야 한다. 왜냐하면 학부모 상담 시 객관적 데이터가 필요하기 때문이다.

### FEAT-4: 학원 내 상점 (v2)
- [ ] 학생으로서, 모은 포인트로 학원 상점에서 간식을 구매할 수 있어야 한다. 왜냐하면 실제 보상이 학습 동기를 더 강화하기 때문이다.

## 5. 범위 관리

### 5.1 MVP (반드시 포함)
- FEAT-0: 계정 관리 (학원에서 학생 계정 생성·부여, 로그인)
- FEAT-1: 단계적 개념 학습 (읽기→빈칸(쉬움)→빈칸(어려움)→백지 쓰기)
- 게이미피케이션: 포인트(XP)/레벨업/랭킹 시스템

### 5.2 옵션 (시간 허용 시)
- FEAT-2: 연습 문제 풀기
- FEAT-3: 선생님 대시보드 + 학습 진도 관리

### 5.3 Non-goals (명시적 제외)
- 학부모 카카오톡/문자 알림 — MVP에서는 학부모 연동 불필요
- 학원 내 상점 (포인트로 간식 구매) — 포인트 시스템 안정화 후 추가
- 외부 문제 은행 API 연동 — 자체 콘텐츠로 시작
- 실시간 화상 수업 — 자기주도 학습이 핵심이므로 불필요
- 소셜 로그인 — 학원에서 계정을 직접 부여하므로 불필요

## 7. 해결 가설과 실험

### 7.1 가설
> 만약 수학 개념을 "읽기→빈칸(쉬움)→빈칸(어려움)→백지 쓰기"로 단계적으로 학습하고, 각 단계마다 포인트와 레벨업 보상을 제공하면, 학생들의 개념 이해도가 높아지고 학습을 지속하게 될 것이다. 왜냐하면 점진적으로 보조 장치를 줄이는 것이 인지 과학적으로 효과적이고, 게임적 보상이 내재적 동기를 강화하기 때문이다.

### 7.2 실험 루프

| 단계 | 내용 |
|------|------|
| 실험 | 학원 학생 20명에게 MVP를 2주간 사용하게 함 |
| 관측 | 백지 쓰기 도달률, 주간 로그인 횟수, 학생 피드백 |
| 학습 | 백지 도달률 50% 이상이면 성공 / 미만이면 난이도 곡선 재조정 |
| 다음 | 성공 시 콘텐츠 확장, 실패 시 중간 단계(힌트) 추가 가설 테스트 |
