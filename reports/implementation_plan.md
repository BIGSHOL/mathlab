# MathLab 디자인 개선 구현 계획서

본 문서는 `design_improvements.md`에서 제안된 MathLab 관리자 페이지의 UI/UX 개선사항을 전체 시스템에 반영하기 위한 구체적인 기술적 접근 방안을 정의합니다.

## User Review Required
> [!IMPORTANT]
> 다크 모드(Dark Mode) 도입은 프로젝트 전반의 컬러 테마 시스템(Tailwind CSS 설정 등)을 건드리는 큰 변경 사항입니다.
> 현재 MathLab 프로젝트의 프레임워크와 스타일링 방식(예: Tailwind CSS 사용 여부, `next-themes` 라이브러리 도입 여부 등)에 대한 승인 및 추가 정보가 필요할 수 있습니다.

---

## 🚀 Proposed Changes

디자인 개선을 다음 세 가지 주요 페이즈(Phase)로 나누어 점진적으로 적용합니다.

### Phase 1: Quick Wins (단기 적용 가능한 효과적 개선)

이 단계에서는 CSS 조정 및 간단한 컴포넌트 추가를 통해 즉각적인 UX 향상을 도모합니다.

*   **상태 피드백 강화 및 마이크로 인터랙션 추가**
    *   모든 주요 액션 버튼(저장, 삭제 등)에 `framer-motion` 또는 순수 CSS 변환(transition)을 사용하여 호버(Hover) 및 탭(Tap) 효과를 일관되게 적용합니다.
    *   버튼 클릭 시 로딩 스피너 UI를 버튼 내에 통합합니다.
    *   빈 화면(Empty State) 디자인 컴포넌트를 공통화하여 데이터가 없는 화면(예: 검색 결과 없음, 학생 목록 없음)에 일러스트와 안내 문구를 적용합니다.
*   **정보 밀도 조절 (Compact / Standard Mode)**
    *   데이터 테이블 및 리스트 아이템의 내부 여백(Padding)을 줄인 `Compact` 클래스(또는 속성)를 추가합니다.
    *   설정 패널이나 헤더 상단에 '조밀도(Density) 조절' 토글을 제공하여 이 클래스를 제어합니다.

### Phase 2: Power User Features (사용성 및 효율성 극대화)

관리자의 작업 속도를 실질적으로 높여주는 기능적 UX 향상에 집중합니다.

*   **키보드 단축키(Hotkeys) 지원**
    *   글로벌 검색(`Ctrl+K` / `Cmd+K`): 관리자 페이지 어디서든 학생이나 개념을 찾을 수 있는 Command Palette(예: `cmdk` 패키지 활용)를 도입합니다.
    *   포커스 내비게이션(Focus Navigation): 리스트 항목이나 폼 입력 필드를 키보드 방향키만으로 이동할 수 있도록 접근성 속성(`tabindex`, `aria-*`)과 커스텀 포커스 링 스타일을 손봅니다.
*   **필터 UI 재구성**
    *   복잡한 폼 필터를 '상위 필수 필터'와 '상세 필터(토글식 아코디언 패널)'로 분리하여 기본 화면 공간을 확보합니다.

### Phase 3: Major Architectural UI Updates (레이아웃 및 테마 고도화)

기반 레이아웃과 전체 테마 시스템을 개선하는 대규모 작업입니다.

*   **다크 모드 (Dark Mode) 스캐폴딩 및 적용**
    *   시스템 환경 설정 또는 사용자 전용 토글에 따라 반응하는 다크 모드를 구현합니다. (Next.js 환경이라면 `next-themes` 사용 검토).
    *   `tailwind.config.ts` (또는 CSS 변수)에 Dark 모드용 시맨틱 컬러 팔레트를 정의하고, 기존 하드 코딩된 컬러를 변수로 치환합니다.
*   **완전한 반응형 레이아웃 구축**
    *   태블릿(iPad) 이하의 해상도(breakpoint `< 1024px`)에서 왼쪽 사이드바가 햄버거 메뉴 또는 바텀 시트로 접히는 로직을 구현합니다.
    *   마스터-디테일(2패널) 뷰에서 모바일 단말 접근 시, 리스트 클릭 후 디테일 뷰를 모달이나 전체 화면 오버레이로 띄우는 네비게이션 구조로 전환합니다.

## 🧪 Verification Plan

각 페이즈별 개발 완료 후 다음과 같은 방법으로 검증합니다.

### Manual Verification
1.  **시각적 검토:**
    *   브라우저의 모바일 환경에뮬레이터(DevTools)를 이용하여 사이드바가 메뉴로 잘 숨겨지는지 확인.
    *   테이블 항목 행 간격이 'Compact Mode' 옵션에 따라 달라지는지 육안 확인.
    *   다크 모드 토글 전환 시 눈이 쨍한 컬러가 남은 곳이 없는지 전수 검사 (특히 텍스트 콘트라스트 통과 여부 검사).
2.  **동작 검토:**
    *   '학생 검색' 등 지정된 단축키(`Ctrl+K`)가 모든 메뉴 탭에서 정상 레이어팝업을 호출하는지 키보드 테스트 진행.
    *   키보드 탭(Tab) 키만으로 폼 영역 진입 후 저장이 가능한지 접근성 테스트.

### Automated Tests
1.  **UI/E2E 테스트:** Playwright 등 프로젝트 설정에 등록된 도구로 로그인 후 다크모드 토글 스크립트 실행 테스트, 반응형 Width 조절에 따른 컴포넌트 렌더링 검증.
2.  **접근성(a11y) 검사:** Lighthouse 나 axe-core 모듈을 이용해 개선 후 색상 대비 및 포커스 영역에서 접근성 점수 개선치를 측정합니다.
